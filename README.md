# PhotoView on Railway

A Railway template for [PhotoView](https://github.com/photoview/photoview), a self-hosted photo gallery for your own server. This repo is what the template builds: the official PhotoView image plus a small wrapper.

## What it deploys

| Service | Source | Notes |
|---|---|---|
| `PhotoView` | this repo (`Dockerfile`) | PhotoView **2.4.0** (`photoview/photoview:2.4.0@sha256:31c0c4fd…`), public HTTPS domain, one volume at `/data` |
| `Postgres` | Railway Postgres | PhotoView's database |

Inside the PhotoView container:

- **PhotoView** listens on `127.0.0.1:8081`.
- **WebDAV** (`rclone serve webdav`, rclone 1.76.0) listens on `127.0.0.1:8082` and serves the photo folder at `/webdav`, so you can upload photos from Finder, Windows Explorer, a phone app or `rclone`.
- **Caddy** 2.11.9 is the only public listener (`$PORT`, default 8080). It sends `/webdav*` to WebDAV and everything else to PhotoView.

All three are pinned by version and digest in the `Dockerfile`.

The volume holds:

- `/data/photos`: your photos and videos (PhotoView's root folder, and the WebDAV root)
- `/data/cache`: PhotoView's thumbnails and transcoded videos

## No open setup wizard

PhotoView normally shows a public "initial setup" page where the first visitor picks the admin account. Here the start script finishes that setup itself, on localhost, **before** the public port opens:

- user `ADMIN_USERNAME` (default `admin`)
- password `ADMIN_PASSWORD` (generated by Railway when you deploy)
- photo folder `/data/photos`
- automatic scan every 15 minutes (`PERIODIC_SCAN_SECONDS`, default 900; change it later in PhotoView's Settings)

The same username and password protect WebDAV.

## Variables

| Variable | Default | What it does |
|---|---|---|
| `PHOTOVIEW_POSTGRES_URL` | `${{Postgres.DATABASE_URL}}` | Database connection (private network) |
| `ADMIN_PASSWORD` | `${{secret(24,…)}}` | Password of the PhotoView admin and of WebDAV. Read it in the service's Variables tab |
| `ADMIN_USERNAME` | `admin` | Admin username, used once at first start, and for WebDAV |

Notes:

- `ADMIN_USERNAME` and `ADMIN_PASSWORD` set up PhotoView **once**. After that, change the PhotoView password in PhotoView itself. WebDAV always uses the current values of the two variables.
- Optional: set `MAPBOX_TOKEN` to enable PhotoView's map view ([free token](https://account.mapbox.com/access-tokens/)).
- Optional: `PHOTOVIEW_DISABLE_FACE_RECOGNITION=1`, `PHOTOVIEW_DISABLE_VIDEO_ENCODING=1` or `PHOTOVIEW_DISABLE_RAW_PROCESSING=1` to save CPU.

## Adding photos

PhotoView shows the photos that are in its folder; it has no upload button. Upload over WebDAV:

- **macOS Finder:** Go → Connect to Server → `https://YOUR-DOMAIN/webdav/`
- **Windows:** map a network drive to `https://YOUR-DOMAIN/webdav/`
- **rclone:** `rclone copy ./Pictures :webdav,url=https://YOUR-DOMAIN/webdav,user=admin,pass=$(rclone obscure 'YOUR-PASSWORD'): -P`

Then wait for the next automatic scan, or press **Scan** under Settings in PhotoView.

## Updates

Each change to this repo's `main` branch is a new template version. Railway shows deployers an "update available" notice and they choose when to apply it. Read [CHANGELOG.md](CHANGELOG.md) first: breaking changes are listed at the top of each entry.

The upstream image is pinned by digest. Docker Hub rebuilds the `2.4.0` tag from time to time (same PhotoView code, newer base packages), so a later version of this repo may move the digest without a PhotoView version change.
